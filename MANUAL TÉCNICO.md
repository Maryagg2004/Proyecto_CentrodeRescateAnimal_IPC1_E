# Manual técnico — Centro de Rescate Animal

| No. | Sección                        | Información técnica del proyecto                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| ---:| ------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | Portada                        | **Nombre del sistema:** Centro de Rescate Animal: Gestión de Refugio y Adopciones.<br>**Institución:** Universidad de San Carlos de Guatemala.<br>**Facultad:** Facultad de Ingeniería.<br>**Carrera:** Ingeniería en Ciencias y Sistemas.<br>**Curso:** Introducción a la Programación y Computación 1.<br>**Carné:** 202500170.<br>**Semestre:** Segundo semestre de 2026.<br>**Versión:** 1.0.<br>**Fecha:** Septiembre de 2026.                                                                                                                                                                |
| 2   | Introducción                   | El presente manual técnico documenta la estructura y el funcionamiento interno del sistema Centro de Rescate Animal. La aplicación fue desarrollada en Java y utiliza Java Swing para construir su interfaz gráfica mediante código. El sistema administra usuarios, animales rescatados, adoptantes, solicitudes de adopción, rescates urgentes, espacios físicos y bitácoras. Los registros principales se almacenan en arreglos y matrices estáticas, sin utilizar estructuras dinámicas pertenecientes al Java Collections Framework.                                                          |
| 3   | Objetivo general               | Documentar la arquitectura, clases, métodos, arreglos, matrices, validaciones, reglas de negocio, archivos y procedimientos técnicos del sistema, para facilitar su comprensión, ejecución, mantenimiento y ampliación.                                                                                                                                                                                                                                                                                                                                                                            |
| 4   | Objetivos específicos          | Describir las tecnologías utilizadas; identificar las responsabilidades de cada clase; documentar los atributos y métodos principales; explicar las dimensiones de los arreglos y matrices; presentar las validaciones y reglas de negocio; explicar el manejo de bitácoras y reportes HTML; documentar la instalación, compilación y ejecución; e identificar las limitaciones de la versión actual.                                                                                                                                                                                              |
| 5   | Alcance del sistema            | El sistema incluye autenticación local, gestión de animales, gestión de adoptantes, solicitudes de adopción, rescates urgentes, ubicaciones del refugio, bitácora de acciones, bitácora de errores y exportación de las bitácoras a HTML. La aplicación funciona localmente y no requiere servidor, conexión a Internet ni sistema gestor de bases de datos.                                                                                                                                                                                                                                       |
| 6   | Requisitos técnicos            | **Lenguaje:** Java.<br>**Versión utilizada:** OpenJDK 21.<br>**Versión mínima:** Java 17.<br>**Interfaz:** Java Swing.<br>**IDE:** Visual Studio Code.<br>**Control de versiones:** Git y GitHub.<br>**Sistema operativo:** Windows, GNU/Linux o macOS.<br>**RAM recomendada:** 4 GB.<br>**Almacenamiento:** aproximadamente 200 MB.<br>**Navegador:** requerido para abrir los reportes HTML.                                                                                                                                                                                                     |
| 7   | Tecnologías utilizadas         | **Java:** implementación de clases, métodos, arreglos, matrices, ciclos y validaciones.<br>**Java Swing:** creación de menús, formularios y mensajes.<br>**Archivos TXT:** persistencia de acciones y errores.<br>**HTML:** estructura de los reportes generados.<br>**CSS:** formato visual de las tablas de los reportes.<br>**Git/GitHub:** control y evidencia de los cambios del proyecto.                                                                                                                                                                                                    |
| 8   | Restricciones técnicas         | La lógica principal utiliza exclusivamente arreglos estáticos y matrices. No se emplean `ArrayList`, `LinkedList`, `HashMap`, `List`, `Queue`, `Stack`, `Vector` ni otras estructuras del Java Collections Framework. La interfaz gráfica se construye manualmente con código Java Swing y no utiliza herramientas visuales de arrastrar y soltar.                                                                                                                                                                                                                                                 |
| 9   | Arquitectura del sistema       | La aplicación utiliza una arquitectura modular. `Main` funciona como controlador y capa de presentación. Las clases `Usuario`, `Animales`, `Adoptante`, `Solicitud`, `Rescate` y `EspacioRefugio` contienen la lógica y el almacenamiento en memoria. `Bitacora` se encarga de la persistencia en archivos y de generar los reportes HTML. `Main` también controla las reglas que necesitan comunicación entre varios módulos.                                                                                                                                                                     |
| 10  | Diagrama de arquitectura       | `Usuario → Interfaz Java Swing → Main → Clases de lógica y almacenamiento`. Desde `Main` se utilizan `Animales`, `Adoptante`, `Solicitud`, `Rescate`, `EspacioRefugio`, `Usuario` y `Bitacora`. La clase `Bitacora` escribe información en archivos TXT y genera archivos HTML.                                                                                                                                                                                                                                                                                                                    |
| 11  | Estructura del proyecto        | El proyecto está compuesto por ocho archivos principales: `Main.java`, `Usuario.java`, `Animales.java`, `Adoptante.java`, `Solicitud.java`, `Rescate.java`, `EspacioRefugio.java` y `Bitacora.java`. Durante la ejecución también pueden crearse `bitacora_acciones.txt`, `bitacora_errores.txt`, `reporte_acciones.html` y `reporte_errores.html`.                                                                                                                                                                                                                                                |
| 12  | Convención para los resultados | Los métodos de las clases de lógica utilizan la convención `null = éxito`. Cuando ocurre un error, devuelven una cadena con la estructura `EVENTO:descripción`. Las categorías utilizadas son `VALIDACION`, `DUPLICADO`, `CAPACIDAD`, `ESTADO` y `PERMISO`. El método `procesarResultado()` de `Main` separa el evento y la descripción, registra la operación en la bitácora correspondiente y muestra un diálogo.                                                                                                                                                                                |
| 13  | Clase `Main`                   | Es el controlador principal. Crea una instancia estática de `Animales`, `Adoptante`, `Solicitud`, `Rescate`, `EspacioRefugio` y `Usuario`. El método `main()` ejecuta la autenticación y muestra el menú principal. Sus submenús permiten ingresar a animales, adoptantes, solicitudes, rescates, ubicaciones y bitácoras. También coordina reglas que necesitan información de varias clases.                                                                                                                                                                                                     |
| 14  | Métodos principales de `Main`  | `main()` inicia el sistema; `iniciarSesionInteractiva()` controla el acceso; `menuAnimales()` administra las opciones de animales; `menuAdoptantes()` administra adoptantes; `menuSolicitudes()` administra solicitudes; `menuRescates()` administra rescates; `menuUbicaciones()` administra espacios; `menuBitacora()` genera reportes; `mostrarMenu()` construye los menús; `leerOpcion()` convierte la opción a entero; `pedirDatos()` genera formularios; `mostrarListado()` presenta información; y `procesarResultado()` gestiona éxitos y errores.                                         |
| 15  | Clase `Usuario`                | Administra la autenticación y los permisos. Utiliza tres arreglos paralelos para usuarios, contraseñas y roles. Tiene una capacidad de dos usuarios y permite un máximo de tres intentos fallidos. Al alcanzar el límite, la sesión se bloquea hasta que la aplicación se reinicia. También almacena el usuario y el rol de la sesión actual.                                                                                                                                                                                                                                                      |
| 16  | Usuarios precargados           | **Administrador:** usuario `admin1`, contraseña `Refugio2026` y rol `ADMIN`.<br>**Auxiliar:** usuario `auxiliar1`, contraseña `Auxiliar2026` y rol `AUXILIAR`.<br>El administrador puede dar de baja animales. El auxiliar no tiene autorización para ejecutar esa operación.                                                                                                                                                                                                                                                                                                                      |
| 17  | Métodos de `Usuario`           | `validarUsuario()` comprueba entre 4 y 15 caracteres alfanuméricos; `validarContrasena()` exige al menos 6 caracteres; `iniciarSesion()` verifica las credenciales; `registrarIntentoFallido()` incrementa el contador; `estaBloqueado()` consulta el bloqueo; `obtenerUsuarioActual()` devuelve el usuario autenticado; y `obtenerRolActual()` devuelve su rol.                                                                                                                                                                                                                                   |
| 18  | Clase `Animales`               | Gestiona el registro, búsqueda, modificación, listado y baja lógica de los animales. Utiliza una matriz `String[10][5]`. Puede almacenar como máximo diez animales, y cada registro contiene cinco atributos. El estado inicial de adopción se asigna automáticamente como `DISPONIBLE`.                                                                                                                                                                                                                                                                                                           |
| 19  | Matriz de `Animales`           | **Dimensiones:** 10 filas × 5 columnas.<br>**Capacidad:** 10 animales.<br>**Columna 0:** código.<br>**Columna 1:** especie.<br>**Columna 2:** edad.<br>**Columna 3:** estado clínico.<br>**Columna 4:** estado de adopción.<br>El contador `cantidadAnimales` identifica cuántas filas están ocupadas.                                                                                                                                                                                                                                                                                             |
| 20  | Métodos de `Animales`          | `validacionCodigo()` valida `A-000`; `validacionEspecie()` valida Perro o Gato; `especieEdad()` valida una edad de 0 a 25; `estadoclinico()` valida el estado clínico; `estadoAdopcion()` valida el estado de adopción; `existeCodigo()` comprueba duplicados; `buscarAnimal()` devuelve la fila; `registrarAnimal()` guarda un animal; `editarEstadoClinico()` modifica el estado clínico; `editarEstadoAdopcion()` modifica el estado de adopción; `eliminarAnimalLogico()` marca el registro como eliminado; y `listarAnimales()` genera el listado.                                            |
| 21  | Validaciones de animales       | El código debe cumplir `A-[0-9]{3}`. La especie puede ser `Perro` o `Gato`. La edad debe ser un entero entre 0 y 25. Los estados clínicos permitidos son `EN_OBSERVACION`, `EN_TRATAMIENTO` y `APTO`. Los estados de adopción permitidos son `DISPONIBLE`, `ADOPTADO` y `ELIMINADO`. El código no puede repetirse.                                                                                                                                                                                                                                                                                 |
| 22  | Baja lógica de animales        | La eliminación no borra físicamente una fila. `eliminarAnimalLogico()` cambia el estado de adopción a `ELIMINADO`. El código permanece almacenado y no puede utilizarse para registrar otro animal. Un animal eliminado no puede volver a modificarse. Cuando se elimina, `Main` solicita a `EspacioRefugio` que libere su ubicación.                                                                                                                                                                                                                                                              |
| 23  | Clase `Adoptante`              | Gestiona el registro, búsqueda, edición y listado de personas interesadas en adoptar. Utiliza una matriz `String[10][4]`. El código y el DPI se consideran datos de identidad y no pueden editarse. Solamente pueden modificarse el nombre y el teléfono. El módulo no permite eliminar adoptantes.                                                                                                                                                                                                                                                                                                |
| 24  | Matriz de `Adoptante`          | **Dimensiones:** 10 filas × 4 columnas.<br>**Capacidad:** 10 adoptantes.<br>**Columna 0:** código.<br>**Columna 1:** nombre.<br>**Columna 2:** DPI.<br>**Columna 3:** teléfono.<br>El contador `cantidadAdoptantes` controla las filas ocupadas.                                                                                                                                                                                                                                                                                                                                                   |
| 25  | Métodos de `Adoptante`         | `validarCodigo()` comprueba `AD-000`; `validarNombre()` permite letras, tildes y espacios; `validarDpi()` exige 13 dígitos; `validarTelefono()` exige 8 dígitos; `existeCodigo()` comprueba códigos; `buscarAdoptante()` devuelve la fila; `existeDpi()` identifica duplicados; `registrarAdoptante()` guarda el registro; `editarAdoptante()` modifica nombre y teléfono; `obtenerAdoptanteFormateado()` prepara los datos; y `listarAdoptantes()` genera el listado.                                                                                                                             |
| 26  | Validaciones de adoptantes     | El código debe cumplir `AD-[0-9]{3}`. El nombre solamente admite letras, caracteres con tilde, letra ñ y espacios. El DPI debe contener exactamente 13 dígitos y debe ser único. El teléfono debe contener exactamente 8 dígitos. Los campos no pueden ser nulos o vacíos.                                                                                                                                                                                                                                                                                                                         |
| 27  | Clase `Solicitud`              | Gestiona el registro y seguimiento de solicitudes de adopción. Utiliza una matriz `String[15][5]`. Toda solicitud se registra inicialmente como `PENDIENTE`. Permite aprobar, rechazar o completar solicitudes y consultar las pendientes o el historial completo.                                                                                                                                                                                                                                                                                                                                 |
| 28  | Matriz de `Solicitud`          | **Dimensiones:** 15 filas × 5 columnas.<br>**Capacidad:** 15 solicitudes.<br>**Columna 0:** código de solicitud.<br>**Columna 1:** código del animal.<br>**Columna 2:** código del adoptante.<br>**Columna 3:** fecha.<br>**Columna 4:** estado.<br>El contador `cantidadSolicitudes` controla las filas utilizadas.                                                                                                                                                                                                                                                                               |
| 29  | Métodos de `Solicitud`         | `validarCodigo()` comprueba `S-000`; `validarEstado()` comprueba los estados; `validarFecha()` valida la fecha; `existeSolicitud()` comprueba duplicados; `buscarSolicitud()` devuelve la fila; `registrarSolicitud()` guarda la información; `aprobarSolicitud()` aprueba y rechaza otras solicitudes; `rechazarSolicitud()` cambia el estado a rechazada; `completarSolicitud()` finaliza una solicitud aprobada; `obtenerCodigoAnimal()` consulta la relación; `obtenerEstado()` consulta el estado; `listarSolicitudes()` muestra el historial; y `listarPendientes()` muestra las pendientes. |
| 30  | Validación de fechas           | Las fechas deben utilizar el formato `dd/mm/aaaa`. El método `validarFecha()` comprueba la estructura, el número de mes, la cantidad de días correspondiente y los años bisiestos. Por ello, una fecha inexistente como `31/02/2026` es rechazada.                                                                                                                                                                                                                                                                                                                                                 |
| 31  | Estados de solicitudes         | Los estados permitidos son `PENDIENTE`, `APROBADA`, `RECHAZADA` y `COMPLETADA`. Para aprobar o rechazar, la solicitud debe encontrarse pendiente. Para completar, debe estar aprobada. No se permite saltar directamente de pendiente a completada.                                                                                                                                                                                                                                                                                                                                                |
| 32  | Aprobación de solicitudes      | Cuando se aprueba una solicitud, su estado cambia a `APROBADA`. Las demás solicitudes pendientes del mismo animal cambian automáticamente a `RECHAZADA`. Posteriormente, `Main` modifica el estado del animal a `ADOPTADO` y libera su celda en la matriz de ubicaciones.                                                                                                                                                                                                                                                                                                                          |
| 33  | Clase `Rescate`                | Gestiona los reportes de rescates urgentes. Utiliza una matriz `String[10][5]`. Cada rescate se registra como `PENDIENTE`. Al atenderlo, cambia a `ATENDIDO` y queda relacionado con un código existente o generado en el módulo de animales.                                                                                                                                                                                                                                                                                                                                                      |
| 34  | Matriz de `Rescate`            | **Dimensiones:** 10 filas × 5 columnas.<br>**Capacidad:** 10 rescates.<br>**Columna 0:** código.<br>**Columna 1:** prioridad.<br>**Columna 2:** estado.<br>**Columna 3:** fecha del reporte.<br>**Columna 4:** código del animal vinculado.<br>El contador `cantidadRescates` controla los registros.                                                                                                                                                                                                                                                                                              |
| 35  | Métodos de `Rescate`           | `validarCodigo()` valida `R-000`; `validarPrioridad()` valida la prioridad; `existeCodigo()` comprueba duplicados; `buscarRescate()` devuelve la fila; `registrarRescate()` registra el caso; `atenderRescate()` cambia el estado y guarda el animal; `obtenerCodigoAnimalVinculado()` consulta la relación; `obtenerEstado()` consulta el estado; `listarReportesActivos()` presenta casos pendientes; `listarTodos()` muestra el historial; y `formatear()` construye la representación de cada registro.                                                                                        |
| 36  | Reglas de rescates             | Las prioridades permitidas son `ALTA`, `MEDIA` y `BAJA`. Los estados permitidos son `PENDIENTE` y `ATENDIDO`. Los rescates activos se muestran primero por prioridad alta, luego media y finalmente baja. Un rescate atendido no puede atenderse nuevamente.                                                                                                                                                                                                                                                                                                                                       |
| 37  | Vinculación de rescates        | Al atender el rescate `R-009`, `Main` genera el código `A-009`. Si el código ya existe, el rescate se vincula con ese animal. Si no existe, el sistema solicita especie, edad y estado clínico, registra el animal y trata de asignarle una ubicación automáticamente.                                                                                                                                                                                                                                                                                                                             |
| 38  | Clase `EspacioRefugio`         | Administra las ubicaciones físicas del refugio. Utiliza una matriz `String[2][5]`. Cada fila representa una zona y cada columna una jaula o espacio. Una cadena vacía indica que la celda se encuentra libre.                                                                                                                                                                                                                                                                                                                                                                                      |
| 39  | Matriz de ubicaciones          | **Dimensiones:** 2 filas × 5 columnas.<br>**Capacidad total:** 10 espacios.<br>**Fila 0:** Zona Perros.<br>**Fila 1:** Zona Gatos.<br>**Columnas válidas:** 0, 1, 2, 3 y 4.<br>**Representación de una celda libre:** `""`.<br>**Representación de una celda ocupada:** código del animal.                                                                                                                                                                                                                                                                                                         |
| 40  | Métodos de `EspacioRefugio`    | `filaSegunEspecie()` determina la zona; `nombreZona()` devuelve su nombre; `asignarEspacio()` busca automáticamente una celda libre; `asignarManual()` utiliza una posición específica; `liberarEspacioPorAnimal()` busca y libera una celda; `obtenerAnimalEnCelda()` devuelve su contenido; y `listadoOcupacion()` presenta todos los espacios.                                                                                                                                                                                                                                                  |
| 41  | Asignación automática          | La especie determina la fila correspondiente. Los perros se asignan a la fila 0 y los gatos a la fila 1. El sistema recorre las cinco columnas y utiliza la primera celda libre. Si la zona está llena, devuelve un error de capacidad.                                                                                                                                                                                                                                                                                                                                                            |
| 42  | Asignación manual              | La fila debe estar entre 0 y 1, y la columna entre 0 y 4. La celda debe encontrarse vacía. Cuando la posición es inválida se devuelve un error de validación. Cuando está ocupada se devuelve un error de capacidad con el código del animal que ocupa la celda.                                                                                                                                                                                                                                                                                                                                   |
| 43  | Clase `Bitacora`               | Registra acciones exitosas y errores. Todos sus métodos son estáticos y el constructor es privado para impedir que se creen instancias. Utiliza `LocalDateTime`, `DateTimeFormatter`, `FileWriter`, `FileReader` y `BufferedReader`.                                                                                                                                                                                                                                                                                                                                                               |
| 44  | Archivos de bitácora           | **Acciones:** `bitacora_acciones.txt`.<br>**Errores:** `bitacora_errores.txt`.<br>Los archivos se crean en el directorio desde el cual se ejecuta el programa. El modo de escritura agrega nuevas líneas y conserva las entradas anteriores.                                                                                                                                                                                                                                                                                                                                                       |
| 45  | Formato de bitácora            | Cada entrada utiliza el formato `fecha\|usuario\|módulo\|evento\|detalle`. La fecha se almacena con el patrón `dd/MM/yyyy HH:mm`. Ejemplo: `14/09/2026 10:30\|admin1\|ANIMALES\|ALTA\|Animal A-001 registrado correctamente`.                                                                                                                                                                                                                                                                                                                                                                      |
| 46  | Métodos de `Bitacora`          | `registrarAccion()` registra una operación exitosa; `registrarError()` registra una operación rechazada; `escribirLinea()` agrega una línea al archivo; `exportarAccionesHtml()` genera el reporte de acciones; `exportarErroresHtml()` genera el reporte de errores; y `exportarHtml()` lee las líneas y construye una tabla HTML.                                                                                                                                                                                                                                                                |
| 47  | Persistencia                   | La versión actual guarda permanentemente únicamente las bitácoras. Los animales, adoptantes, solicitudes, rescates y ubicaciones se almacenan en memoria mediante matrices. Esta información se pierde cuando se cierra la aplicación. No se utiliza una base de datos.                                                                                                                                                                                                                                                                                                                            |
| 48  | Reportes HTML                  | La aplicación genera `reporte_acciones.html` y `reporte_errores.html`. Cada archivo incluye codificación UTF-8, título, estilos CSS y una tabla con las columnas Fecha, Usuario, Módulo, Evento y Detalle. Los reportes se sobrescriben cuando se generan nuevamente.                                                                                                                                                                                                                                                                                                                              |
| 49  | Interfaz gráfica               | La aplicación utiliza `JOptionPane` para diálogos, `JPanel` para agrupar elementos, `BoxLayout` para organizar componentes, `JLabel` para mostrar instrucciones, `JTextField` para ingresar información, `JTextArea` para listados y `JScrollPane` para permitir desplazamiento.                                                                                                                                                                                                                                                                                                                   |
| 50  | Formularios reutilizables      | `pedirDatos()` recibe un título y un arreglo de etiquetas. El método crea un arreglo de `JTextField`, agrega cada etiqueta y campo al panel, muestra el formulario y devuelve los valores ingresados en un arreglo de cadenas. Si el usuario presiona Cancelar, devuelve `null`.                                                                                                                                                                                                                                                                                                                   |
| 51  | Manejo de opciones             | `mostrarMenu()` presenta las opciones y un campo de texto. `leerOpcion()` utiliza `Integer.parseInt()` dentro de un `try/catch`. Si el usuario escribe letras, deja el campo vacío o introduce un valor no numérico, devuelve `null` y se presenta el mensaje de opción inválida.                                                                                                                                                                                                                                                                                                                  |
| 52  | Manejo de errores              | Las conversiones numéricas se protegen mediante `try/catch`. Los archivos utilizan `try-with-resources` para cerrarse automáticamente. Los errores funcionales se devuelven como cadenas y son procesados por `Main`. Los errores de escritura de la bitácora se ignoran para evitar un error en cascada.                                                                                                                                                                                                                                                                                          |
| 53  | Flujo general                  | La aplicación inicia en `main()`, solicita las credenciales y comprueba el bloqueo. Si el acceso es correcto, registra `LOGIN_OK` y muestra el menú principal. El usuario selecciona un módulo, ejecuta operaciones y regresa al menú. Al seleccionar Salir, registra `LOGOUT` y termina la ejecución.                                                                                                                                                                                                                                                                                             |

| 55  | Compilación                    | Desde una terminal ubicada en la carpeta del proyecto se puede ejecutar `javac *.java`. También se pueden indicar individualmente los ocho archivos: `javac Main.java Usuario.java Animales.java Adoptante.java Solicitud.java Rescate.java EspacioRefugio.java Bitacora.java`.                                                                                                                                                                                                                                                                                                                    |
| 56  | Ejecución                      | Después de compilar correctamente se debe ejecutar `java Main`. La aplicación presenta el formulario de autenticación. Los archivos TXT y HTML se generan dentro del directorio de ejecución.                                                                                                                                                                                                                                                                                                                                                                                                      |
| 57  | Pruebas técnicas principales   | Deben probarse: login correcto; tres intentos incorrectos; registro válido de animales; códigos duplicados; edad no numérica; animal eliminado; DPI duplicado; solicitud para animal no disponible; aprobación y rechazo de solicitudes; rescate atendido; zona llena; celda ocupada; baja intentada por un auxiliar; exportación de acciones y exportación de errores.                                                                                                                                                                                                                            |
| 58  | Limitaciones actuales          | Los datos de animales, adoptantes, solicitudes, rescates y ubicaciones no tienen persistencia. Solamente existen reportes HTML de bitácoras. No existen reportes HTML de animales, adopciones y ocupación. `listarAnimales()` incluye animales eliminados. La asignación manual no comprueba que el animal exista, que corresponda a la zona seleccionada o que no ocupe otra celda. Algunos errores de búsqueda no se registran en la bitácora.                                                                                                                                                   |
